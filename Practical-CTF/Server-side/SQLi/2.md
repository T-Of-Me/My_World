# MySQL truncates a string value given a byte value above 0x7F 
- MySQL có vẻ cắt ngắn chuỗi khi gặp byte có giá trị trên `0x7F` (đặc biệt là `\x80`), và bỏ qua tất cả ký tự phía sau byte đó.
- Giải thích về UTF-8 , Tại sao \x80 gây vấn đề?
    - Byte ASCII: Các byte từ 0x00-0x7F là ký tự ASCII hợp lệ (1 byte)
    - Byte `\x80`: Trong UTF-8, byte này là `continuation byte` (byte tiếp theo) - nó phải đi sau một `start byte` (byte bắt đầu) để tạo thành ký tự nhiều byte
    - Vấn đề: Khi `\x80` đứng sau ký tự `ASCII` (như chữ "n" trong "admin"), nó tạo ra chuỗi `UTF-8` không hợp lệ
- Quy tắc `UTF-8`:
    - Byte <= `0x7F`: Ký tự đơn (ASCII)
    - Byte `0xC2-0xF4`: Start byte cho ký tự nhiều byte
    - Byte `0x80-0xBF`: Continuation byte (phải đi sau start byte)
- Điều kỳ lạ:
- Trong lịch sử, `MySQL` cũ (trước 5.7/2013) có thể tự động cắt chuỗi khi gặp UTF-8 không hợp lệ
- MySQL 5.7+ đã bật strict mode mặc định, lẽ ra không còn hành vi này
- Khi test bằng command line, MySQL không cắt chuỗi vẫn hiển thị đầy đủ
- Nhưng khi query từ PHP thì lại bị cắt

```code
<?php
// Kết nối MySQL
$conn = new mysqli("localhost", "user", "password", "database");

// Truy vấn với byte \x80 - Bypass authentication
$username = "admin\x80foobar";  // Byte \x80 và dữ liệu sau nó
$password = "anything";

// Query SQL
$query = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";
$result = $conn->query($query);

if ($result->num_rows > 0) {
    echo "Login successful!";
    // MySQL có thể so sánh 'admin\x80foobar' == 'admin' 
    // => Bypass authentication!
}
?>
```
